# v1.1.0 High-Concurrency Audit & Hardening Plan (2026-06-17)

Goal: make qbuem-stack safe, robust, and fast under **tens of thousands of
concurrent connections**, add missing high-level APIs, then release v1.1.0.
Source: 5 parallel read-only subsystem audits (server, net/io/shm, core runtime,
pipeline/middleware, DoS+db/crypto). Every finding below was code-verified
(file:line quoted by the auditor).

Legend: **[FIX]** = land in v1.1.0 · **[DEFER]** = honestly out of scope for a
hardening release (documented, not faked).

## P1 — concurrency hotspots / safety / missing high-level

**Concurrency/safety [FIX]:**
- P1-a awaiters register+unregister **per op** (epoll_ctl ADD/DEL + `std::function` alloc each read/write/accept) — awaiters.hpp:44-142. (Servers App/WsServer already use persistent callbacks; this hits TcpStream/UDP users.)
- P1-b DNS thread-per-resolve, detached, UAF-on-teardown — net/dns.hpp:110-168.
- P1-c MessageBus::publish copies all `std::function` into 2 vectors/msg — pipeline/message_bus.hpp:214-236.
- P1-d CircuitBreaker `record_*` mutex every call — pipeline/circuit_breaker.hpp:95-136.
- P1-e BackpressureMonitor::stage() mutex + `std::string`/call (doc claims lock-free) — pipeline/backpressure_monitor.hpp:311-322.
- P1-f WS upgrade reader: no idle/slowloris timeout — server/ws_server.hpp:1048-1091.
- P1-g shm_bus LocalSub/SystemSub store dangling `const char*` topic name — shm/shm_bus.hpp:295-346.
- P1-h kqueue `entry_map_` dense vector never shrinks (high-fd → permanent big alloc) — src/core/kqueue_reactor.cpp.
- P1-i TcpListener accept EMFILE hot-spin (no backoff); TcpStream no read timeout — net/tcp_listener.hpp, tcp_stream.hpp.
- P1-j AsyncFile/DirectFile blocking pread/pwrite reachable on reactor thread — io/async_file.hpp, direct_file.hpp. (Document: offload-only.)
- P1-k UDS recv_fds blocking `MSG_WAITALL` — net/uds_advanced.hpp:251. (Document: offload-only.)
- P1-l PipelineGraph fanout copies item via `std::any` per item — pipeline/pipeline_graph.hpp:583-595.

**Missing high-level [FIX]:**
- HL-1 TcpStream `read_exact`/`read_until`/`write_all` + buffered helpers — net/tcp_stream.hpp.
- HL-2 `AcceptLoop::run()` is a stub — implement a working reactor-driven generic accept loop, or convert to a documented helper. connection_handler.hpp:129-176.
- HL-3 JWT signer/verifier `HmacJwtVerifier` + `encode_jwt` over existing HMAC (reject alg=none) — security/.
- HL-4 AEAD misuse-resistant `seal_easy`/`open_easy` (random nonce) + `password_hash`/`verify_password` over PBKDF2 — crypto/.
- HL-5 DB ConnectionPool: implement waiter queue / backpressure (acquire currently hard-errors); wire idle cleanup. db/connection_pool.hpp.

**Missing high-level [DEFER] — honestly out of scope for a hardening release; documented, not faked:**
- HL-D1 Full **HTTP/2 server** transport (socket loop, flow control, ALPN/TLS, App wiring). Http2Handler stays a codec/state-machine; we harden its DoS surface (P0-4/5) and document "not a wired server yet."
- HL-D2 Full **gRPC server** transport (depends on HL-D1). Fix overflow (P0-3); document codec-only.
- HL-D3 Concrete **DB driver**. Layer is BYO-driver interfaces; fix the pool + document.

## Implementation batches (each: -Werror build + ctest + ASan/UBSan + commit)

- **Batch A — security P0s (low-risk, bounded):** P0-3 gRPC overflow, P0-7 PBKDF2 cap, P0-6 RUDP cap, P0-5 HPACK overflow + HTTP/2 frame/body/header caps, P0-4 Rapid Reset (erase streams + max-concurrent + RST rate-limit), P1-g shm_bus name, Arena overflow guard.
- **Batch B — core scale:** P0-2 TimerWheel O(1) next_expiry, P1-h kqueue entry_map, P0-1 App non-blocking buffered write path.
- **Batch C — IPC/pipeline:** P0-10 SHM real futex (FutexSync), P0-9 pipeline timer (no busy-spin), P0-8 idempotency bound, P1-c/d/e/l hotspots.
- **Batch D — high-level APIs:** HL-1 TcpStream helpers, HL-2 AcceptLoop, HL-3 JWT, HL-4 AEAD-easy, HL-5 DB pool, P1-f WS upgrade timeout, P1-b DNS bound, P1-i/j/k safety+docs.
- **Batch E — release:** docs sync, bench sanity, version 1.1.0 (already bumped), merge, tag.

Deferred items get an explicit `// TODO(v1.2): ...` and a doc note — no false "production h2/grpc/db server" claim (§21).

## DELIVERED in v1.1.0 (verified: -Werror build · ctest 35/35 · full ASan+UBSan 35/35)

- **WS high-level server** — `WsServer`/`WsConnection` (non-blocking, rooms,
  broadcast, back-pressure, heartbeat, fragmentation, strict RFC 6455, UTF-8).
- **Batch A security** — gRPC length 64-bit overflow guard; HTTP/2 Rapid Reset
  (stream erase + RST rate-limit) + MAX_CONCURRENT_STREAMS + DATA/CONTINUATION
  caps + HPACK varint overflow; RUDP reorder-window bound; PBKDF2 iteration cap;
  shm_bus topic-name UAF; Arena size-overflow guard.
- **Batch B core** — `TimerWheel::next_expiry_ms()` O(active-timers) → O(1) cached
  (was scanned on every poll).
- **Batch C pipeline/ws** — idempotency store capacity bound (distinct-key OOM);
  stream_ops throttle/debounce/tumbling busy-spin → timer/1 ms poll; WS
  pre-upgrade slowloris timeout.
- **Batch D high-level** — `TcpStream::write_all()` / `read_exact()`.

## DEFERRED to v1.2 (honest — these currently WORK / are mitigated; reworking
them carries regression risk to a release, and the WS path — the game-critical
path — is already fully non-blocking):

- **App HTTP/1.1 async write path (P0-1)** — flagship server still uses blocking
  `write_all`/`writev_response`/`send_file_body`, mitigated by SO_SNDTIMEO 5 s.
  Only stalls under slow-client + large-response; the game uses WsServer (async).
  Rework mirrors WsServer's buffered Write-callback model.
- **SHMChannel real futex (P0-10)** — backpressure uses `AsyncSleep{1ms}` poll
  (works, ~1 ms latency); wiring `FutexSync` needs per-platform care (no Linux
  futex on macOS dev path).
- **Lock-free CircuitBreaker/MessageBus/BackpressureMonitor record paths (P1)** —
  correct under mutex today; lock-free rewrite of a safety primitive is risky
  pre-release.
- **awaiters persistent registration (P1-a)** — per-op register/unregister hits
  only direct TcpStream/UDP users; the servers (App, WsServer) already use
  persistent reactor callbacks.
- **DNS resolver pool (P1-b)**, **AsyncFile/UDS offload docs (P1-j/k)**, **JWT
  signer/verifier (HL-3)**, **AEAD seal_easy/password_hash (HL-4)**, **DB pool
  waiter queue + concrete driver (HL-5)**, **AcceptLoop (HL-2)**, all **P2s**.
- **Full HTTP/2 / gRPC server transport, concrete DB driver** — entire missing
  subsystems (codec/state-machine only today); their DoS surfaces ARE hardened
  in Batch A. Not faked as production servers (§21).
